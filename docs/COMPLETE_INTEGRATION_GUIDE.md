# Scholar9 OJS Integration — Complete Operations Guide

> **ARCHIVED:** This guide describes a superseded full-stack design that modified Scholar9. Those Scholar9 changes have been reverted. Plugin 1.3.2 uses Scholar9's existing API only. Follow [OJS-Only Integration Guide](OJS_ONLY_INTEGRATION_GUIDE.md).

## 1. Purpose and architecture

The Scholar9 Transparent Peer Review plugin provides three connected workflows:

1. **Onboarding:** OJS sends a sanitized journal snapshot and requests API credentials.
2. **Journal sync:** after approval, OJS idempotently updates the corresponding Scholar9 `Journal` and `ReviewerJournal` records.
3. **Peer review:** editors select files and reviewers, exchange messages/files, change reviewers, and receive status updates by webhook or manual sync.

The stable journal identity is derived from the OJS base URL and context ID. Repeated syncs update the same pending request and provisioned journal instead of intentionally creating duplicates. Different contexts in one OJS installation always receive different identities, even when they share the same publisher or contact email.

## 2. Installation

Copy the complete plugin folder to:

```text
<ojs-root>/plugins/generic/scholar9Review
```

Then sign in as a journal manager or administrator, open **Settings > Website > Plugins**, find **Scholar9 Transparent Peer Review** under Generic Plugins, and enable it. Expand the row and confirm **Settings** and **Sync to Scholar9** are visible.

## 3. OJS is the journal-profile source

Do not enter journal directory/profile data in Scholar9 plugin Settings. Maintain it in OJS:

- **Settings > Journal > Masthead:** journal name, acronym, publisher and editorial masthead.
- **Journal contact settings:** primary contact name, email, phone, affiliation and mailing address.
- **Settings > Website > Setup/Appearance:** description/about text and journal image/logo.
- **Settings > Website > Languages:** primary and accepted submission languages.
- **Settings > Distribution > Access/License:** publishing mode, license and copyright policy.
- **Settings > Distribution > Payments:** publication fee/APC configuration.
- **Settings > Distribution > Archiving:** LOCKSS/CLOCKSS configuration.
- **Settings > Distribution > DOI:** DOI configuration.
- **Published issues:** first-publication year and publication-frequency evidence.
- **Published article metadata:** subjects, disciplines and keywords.

COPE compliance, plagiarism screening, an impact factor and recognized indexing URLs are synchronized only when explicitly present in OJS policy/about text. The plugin never invents these claims.

OJS core stores the postal address as one field. Scholar9 receives that full address, while structured state, city and ZIP fields remain blank. Conference charges are also blank because they are not native OJS journal metadata.

## 4. Plugin Settings

Settings intentionally contain integration controls only:

| Setting | Usage |
|---|---|
| Scholar9 Base URL | Scholar9 origin, such as `https://scholar9.example`; do not append `/api` or a journal path. |
| Client ID | Leave empty until Scholar9 approves the request. |
| Client Secret | Leave empty until approval. |
| Journal Slug | Leave empty until approval unless assigned in advance. |
| Webhook Secret | Generated by OJS for HMAC-SHA256 webhook verification. |
| Verify SSL | Keep enabled in production. |
| Default Review Type | Open, single-anonymous, or double-anonymous. |
| Review Deadline | 1–365 days. |
| Auto Sync | Accept verified Scholar9 webhooks. |
| Upload Files | Permit manuscript file transfer. |
| Upload Supplementary | Permit additional selected files. |

Partially entered credentials are rejected. The Base URL accepts only an HTTP(S) origin without credentials, query, fragment, or API path.

## 5. Request API credentials and create the Scholar9 journal

### In OJS

1. Enter the Scholar9 Base URL and save; leave credentials empty.
2. Complete the journal's native OJS metadata.
3. Return to the Plugins list and select **Sync to Scholar9**.
4. Review the complete Scholar9-facing journal profile. Correct any editable value when necessary. These temporary corrections affect the transmitted Scholar9 profile only; update native OJS settings separately when the correction should be permanent.
5. Verify **Journal full name** carefully and submit. It is the sole source for the Scholar9 journal title. Publisher, applicant and contact-person names are distinct fields and are never used as journal-title fallbacks.

After Scholar9 accepts the payload, OJS immediately displays a native success notification. It states whether the API-access request was submitted/updated or an already-authorized journal was synchronized. A failed HTTP, validation or authentication response is never reported as success.

OJS calls `POST /api/ext/register`. It sends the stable source ID, read-only source details and the sanitized profile exactly as reviewed. It never sends a submission, OJS password, webhook secret, session, or private credential. Scholar9 validates the explicit `journal.name` and refuses provisioning when it is absent rather than substituting a person's name.

### In Scholar9

1. Sign in as an administrator.
2. Open **API Management > Pending Requests**.
3. Review the journal snapshot and source identity.
4. Select an active API plan.
5. Select **Approve & Send Credentials**.

Approval claims the pending request to prevent double processing, hashes the generated secret, finds or creates the publisher, creates or updates one `Journal` and one `ReviewerJournal`, associates them with the client, creates or updates one pending plan payment record, and emails the one-time secret, Client ID, API slug and base URL to the OJS contact. The same one-time credentials are also displayed to the approving administrator. Repeated clicks cannot create duplicate journals, profiles, payments or credential emails.

Email delivery is tracked separately from provisioning. If SMTP is unavailable, the approved client and synchronized journal remain valid, the administrator receives an explicit warning, and the one-time credentials remain visible on the redirected Active Clients page for that request. After SMTP is repaired, **Rotate & Email** issues a replacement secret, revokes old tokens and retries delivery. An email outage never resets an approved request to pending or creates duplicate journal records.

### Finish in OJS

Enter the issued Client ID, Client Secret and Journal Slug in plugin Settings, save, and select **Sync to Scholar9** again. Saving registers the webhook. The authenticated sync calls `PUT /api/{journalSlug}/v1/journals/sync` and updates the same journal.

The raw Client Secret is sent once. Scholar9 stores only its hash.

### Multiple journals in one OJS installation

Enable and configure the plugin separately in each journal context. Run **Sync to Scholar9** once from Journal A and once from Journal B. Scholar9 shows two pending request cards because the identity contains the OJS context ID. A second sync from either journal refreshes only that journal's existing pending snapshot. The same manager email may own both journals; an attempt to reuse a journal identity from a different email is rejected as an identity conflict.

Each journal must have its own issued Client ID, Client Secret and Journal Slug saved in that journal's plugin Settings. Never copy Journal A credentials into Journal B.

## 6. Metadata mapping

### Required profile contract

Before OJS can create or refresh an API-access request, the plugin requires reliable native OJS values for:

- journal name and acronym/short name;
- publisher or institution;
- primary contact name and valid email address;
- journal description/about text;
- mailing address and country;
- online ISSN or print ISSN (at least one);
- year of first publication and issue frequency, derived from published OJS issues;
- at least one accepted manuscript language.

Missing values are shown in the native OJS sync dialog and no incomplete request is stored in Scholar9. Scholar9 validates the same contract again during registration, approval, and provisioning, so a stale or manually altered request cannot create a partial directory record. State/province, city, and postal code are not required because OJS core exposes its mailing address as one unstructured field; Scholar9 must not guess those values.

On approval, Scholar9 creates or updates the journal, its public reviewer-journal profile, publisher ownership, stable public slug, serial number, ISSNs, country directory identifiers, and API-client association in one idempotent operation. A public journal is searchable only when it is active, has a stable slug, and has at least one ISSN. Public search matches the journal name, short name, slug/OJS path, source identity, online ISSN, and print ISSN. Its displayed result count is the filtered count, not the global journal count.

| Scholar9 field | Native OJS source | Rule |
|---|---|---|
| name | journal `name` | Unsafe markup is removed; safe OJS path is the fallback if nothing remains. |
| short_name | `acronym`, then `abbreviation` | Primary-locale value. |
| path / URL | context path and OJS base URL | URL-encoded path; HTTP(S) only. |
| description | `description`, then `about` | Plain text, max 4,000 characters. |
| photo_url | header logo, thumbnail, then homepage image | JPG/JPEG/PNG/WebP upload names only. |
| publisher | `publisherInstitution`, contact affiliation, then name | Plain text. |
| contact | OJS contact/support name, email, phone | Email must validate. |
| contact_address | `mailingAddress` | Full address; no city/state guessing. |
| online_issn / print_issn | OJS `onlineIssn` / `printIssn` settings | Revalidated and mapped to Scholar9 `e_issn` / `p_issn`. If OJS has no value, Pending Requests explicitly shows “Not set in OJS”; the plugin never invents an ISSN. |
| locales/languages | primary and supported submission locales | Locale codes and display names. |
| first_publication_year | earliest published issue | Blank without reliable history. |
| issue_frequency | published issues per year | Deterministic inference from available history. |
| subjects | published article subjects/disciplines/keywords | Ranked, unique, maximum 50. |
| editorial_board | OJS 3.5 masthead roles/users | Reviewer-only groups excluded; maximum 100. |
| country | OJS country code | Converted to localized name. |
| open_access | OJS publishing mode | Boolean. |
| open_access_license | license URL, then license terms | HTTP(S) URL preferred; sanitized text otherwise. |
| authors retain rights | copyright holder type | `author=true`, `context/other=false`, else unknown. |
| peer_review | integration purpose | Always true. |
| COPE / plagiarism | explicit journal policy text | True only when explicit, otherwise unknown. |
| impact factor | explicitly labelled journal text | Numeric only; agency only when Clarivate/WoS is explicit. |
| APC | OJS publication fee | True when greater than zero. |
| preservation | LOCKSS or CLOCKSS | Boolean. |
| DOI | OJS DOI setting | Boolean. |
| indexing agencies | recognized profile URLs in policy text | Google Scholar, Scopus, WoS, DOAJ and PubMed only. |

## 7. Review workflow

1. Open **Dashboard > Submissions** and select a submission.
2. Select **Review with Scholar9**.
3. Select **Check for Review** or **Add Review with Scholar9**.
4. Choose one manuscript and an optional plagiarism report.
5. Choose review parameters.
6. Search and select up to five verified Scholar9 reviewers.
7. Confirm.

The OJS journal ID, submission ID, selected files, Scholar9 paper ID, reviewers, messages and status are always scoped to that submission. Moving between submissions cannot reuse another submission's data.

## 8. Conversations, files and reviewer changes

Inside **Review with Scholar9**:

- choose a reviewer/conversation on the left;
- enter plain text and select **Send Message**;
- select **Send File**, choose an existing file belonging to the current submission, and confirm;
- select **Sync conversation** for an immediate API refresh;
- select **Change reviewer** to replace the active reviewer.

The file chooser is an in-page modal. Selecting or cancelling a file does not close the OJS submission drawer. File messages use structured attachment metadata when supported. OJS fallback downloads are signed, submission-bound and expiring.

With Auto Sync enabled, Scholar9 signs webhooks with the configured secret. OJS verifies the signature before updating local state. Manual sync is the fallback when Scholar9 cannot reach OJS.

## 9. Security controls

- Explicit field allow-lists on both applications; whole OJS objects are never serialized.
- Script/style/iframe/object/embed/SVG/MathML blocks, PHP tags, event-handler syntax, JavaScript/HTML-data schemes, controls, bidi override characters and markup are removed or rejected.
- HTTP(S)-only URLs and agency-domain allow-listing for indexing links.
- Length/count limits for text, arrays, board members, subjects, messages, reviewers, deadlines and files.
- Scholar9 validates, rejects executable patterns, sanitizes before storage, then sanitizes again while provisioning.
- Escaped Blade output, CSRF-protected OJS actions and slug-scoped OAuth clients.
- File authorization checks user, journal, submission, file, expiry and signature.
- Hashed Scholar9 secrets; secrets are not logged or returned after issuance.
- Throttled, idempotent public registration.

Production requires HTTPS, CA verification, least-privilege database users, working SMTP, log rotation and a public webhook URL.

## 10. Administrator notification email

Configure Scholar9 `.env`:

```dotenv
SCHOLAR9_API_ADMIN_EMAILS="api-admin@example.org,operations@example.org"
```

Then run `php artisan config:clear`. Scholar9 also discovers eligible administrator emails from its database. A new request sends one notification; repeated OJS syncs refresh the same pending snapshot without email spam.

## 12. Tests and acceptance checklist

From the OJS plugin directory:

```bash
composer test
php tests/metadataProvider.integration.php demo
php tests/metadataProvider.integration.php --all
```

Both metadata commands are read-only. Replace `demo` with one journal path, or use `--all` to validate every context, report whether e-ISSN/p-ISSN exist in native OJS metadata, and prove that all generated journal identities are unique.

From the Scholar9 root:

```bash
php artisan test --filter=OjsApi
php artisan view:cache
php artisan view:clear
```

Manual acceptance:

1. Confirm Settings contains no journal profile-entry fields.
2. Credential-free sync; confirm one pending request.
3. Confirm OJS displays a success notification, then sync again and confirm no duplicate.
4. Repeat from a second OJS journal; confirm two isolated pending cards with different Journal IDs.
5. Approve; confirm publisher, Journal, ReviewerJournal, e-ISSN/p-ISSN mapping and credential email.
6. Click approval again; confirm no second journal, profile, payment or email.
7. Enter credentials and authenticated-sync twice; confirm one profile and current values.
8. Send two OJS submissions; confirm no files, reviewers or conversations mix.
9. Assign reviewers, exchange messages, share a file, change reviewer and test manual/webhook sync.
10. Try encoded script markup, `javascript:` URLs, another submission's file ID, a journal-identity takeover and an invalid webhook signature; each must be removed or rejected.

## 13. Troubleshooting

- **Sync missing:** enable the plugin for this journal, clear OJS caches and reload.
- **Pending request missing:** verify `/api/ext/register` is reachable and inspect Scholar9 `storage/logs/laravel.log`.
- **Unable to authenticate:** use Client ID, Client Secret and slug from the same approved request.
- **Connection timeout on Cloudways or another live host:** configure the public Scholar9 HTTPS origin, not a developer-machine or private-LAN address. Test DNS and TCP/HTTPS access from the OJS server and allow the destination port through outbound and inbound firewall rules. The native sync modal displays the connection failure inline and remains open for retry.
- **Email missing:** verify Laravel SMTP, recipient configuration and logs. Gmail with 2FA requires an app password.
- **Approval cannot email credentials:** copy the one-time credentials displayed on Active Clients before leaving the page. Repair SMTP, then use **Rotate & Email** if a replacement secret must be delivered by email.
- **Second journal is absent:** plugin settings are context-specific. Open that journal, enter its Base URL, save and run **Sync to Scholar9** from that journal's plugin row.
- **cURL error 60:** set `curl.cainfo` and `openssl.cafile` in Apache's active `php.ini`, then restart WAMP.
- **Webhook missing:** remote Scholar9 cannot reach `localhost` or a private LAN-only OJS address.
- **Journal name becomes the path:** the stored title was empty or reduced to nothing after unsafe-markup removal. Correct the native OJS Masthead title and sync again.
- **ISSNs show “Not set in OJS”:** populate the journal's online and print ISSNs in native OJS journal settings, save, then run Sync to Scholar9 again.
- **Some fields blank:** the plugin deliberately does not guess missing structured data or unsupported claims.
